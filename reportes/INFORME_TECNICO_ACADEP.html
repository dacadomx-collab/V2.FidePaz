Arquitectura y saneamiento

V1 — Legacy (dada de baja)

WordPress + WooCommerce en mercagee_colonos (30.7 MB, 55 tablas), con backend de autenticación en Node.js sobre Google Cloud Run. Auditoría de wp_users: 8 de 9 cuentas administrativas con patrón de backdoor confirmado. Redirigida por completo a V2.0; no se reactivó ningún componente de esta arquitectura.

V2.0 — Arquitectura actual

Frontend propio en /panel (HTML/CSS/JS nativo, sin build, sin framework de terceros) + API REST bajo /api/v2. Reemplaza al bundle Angular heredado de la V1 (/administrator, compilado, sin código fuente disponible), retirado como punto de entrada el 2026-08-10 tras 8 fases de reconstrucción módulo por módulo, cada una verificada en vivo contra la API real antes de avanzar a la siguiente. Base de datos consolidada desde mercagee_colonoscore (fuente real, 955 KB) hacia mercagee_v2_FidePaz_DB, con solo 6 tablas de negocio. Backend Go 1.26 + Gin compilado como binario único (arquitectura objetivo, sigue archivado sin exponer en este hosting compartido); backend PHP 8.2 nativo como el que realmente sirve producción hoy — mismo contrato de API, misma seguridad. Actualizado desde PHP 7.4 a 8.2 el 2026-08-05 (soporte de seguridad activo, versión con vida útil vigente).

Seguridad Zero Trust — controles activos

Autenticación

BCrypt (password_verify / bcrypt.CompareHashAndPassword) + JWT HS256 con expiración de 12h.

Acceso a datos

100% de las consultas SQL vía ? parametrizado (PDO / database/sql). Cero concatenación de strings en queries.

Superficie expuesta

28 endpoints explícitos bajo /api/v2, CORS por whitelist dinámica (valida cada Origin contra una lista configurada, nunca refleja sin validar ni usa *), rate limiting por IP en login y contacto.

Migración del panel administrativo (2026-08-08 a 2026-08-10)

De bundle heredado a código propio

/administrator era, literalmente, el mismo bundle Angular compilado de la V1 (hash idéntico contra el respaldo) — nunca se había reconstruido. Reemplazado módulo por módulo (Propietarios, Propiedades, Cuotas, Pagos, Reportes, Comunicados, autoservicio del colono) por HTML/CSS/JS propio, sin build ni dependencias de terceros.

Rollout sin downtime

Cada módulo se desplegó y verificó en vivo (login real, JWT real, CRUD real sobre datos desechables) contra el bundle viejo activo como red de seguridad, antes de retirar el punto de entrada. Cero interrupción de servicio durante la migración.

Desmantelamiento total (Fase 9)

Toda ruta bajo /administrator/* — incluidas las rutas profundas del bundle viejo (/home/quotas, /home/owners, etc.) y los propios chunks compilados — redirige (302) a su equivalente real en /panel/. Los archivos del bundle Angular no se borraron del servidor (evita el riesgo de un borrado remoto no selectivo que pudiera afectar archivos reales no versionados, como .env), pero quedan 100% inalcanzables por HTTP: cero bytes servidos, cero ejecución.

Hitos de infraestructura recientes (2026-08-05)

PHP 7.4 → 8.2

El hosting sí soportaba 8.x (CloudLinux PHP Selector, hasta 8.5); solo nunca se había cambiado. Migrado y re-verificado sin regresión en ningún endpoint.

Motor .xlsx nativo

Los reportes descargables (Pagos, Estado de propietario) generan archivos .xlsx reales con ZipArchive — extensión núcleo de PHP, sin agregar Composer ni librerías de terceros.

Go 1.26 + PHP fallback

Backend Go compilado como binario único (arquitectura objetivo) y backend PHP 8.2 como fallback activo en producción — mismo contrato de API, mantenidos en paralelo mientras el hosting compartido no soporte procesos persistentes propios.
