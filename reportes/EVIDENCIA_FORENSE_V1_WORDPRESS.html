1. Resumen de la auditoría

El sistema anterior de FidePaz no era una aplicación a medida como aparentaba visualmente: era una instalación estándar de WordPress + WooCommerce, con el frontend fuertemente modificado para ocultar su naturaleza real, incluyendo un login de "fachada" que enviaba las credenciales a wp-login.php por debajo. Se realizó una extracción quirúrgica de los datos reales (colonos, propiedades, cuotas) para migrarlos a la arquitectura V2.0, descartando el resto.

4. La fachada: endpoints reales detrás del login

Al decompilar el bundle Angular de la V1 y rastrear las peticiones de red reales, las llamadas del "panel administrativo" apuntaban directo a la REST API nativa de WordPress, no a un backend propio:

GET https://fidepaz.org/wp-json/wp/v2/posts?_embed&categories=39&orderby=date&order=desc&per_page=20
GET https://fidepaz.org/wp-json/wp/v2/posts?_embed&categories=41&orderby=date&order=desc&per_page=1
GET https://fidepaz.org/wp-json/wp/v2/users/{id}

5. Hallazgo adicional: inyección de spam SEO en la taxonomía

Durante esta auditoría se inspeccionó wp_terms (categorías/etiquetas) y se encontró evidencia directa, independiente del hallazgo de cuentas backdoor, de que el sitio fue comprometido para alojar spam SEO de sitios de apuestas: decenas de categorías inyectadas con nombres como 8xbet, rtbet-casino, nha-cai-8xbet, monro-casino, mezcladas entre las categorías legítimas del sitio (Comunicados, financiero, Reportes e Informes). Esto es consistente con un compromiso de larga duración usado para posicionamiento de sitios de terceros aprovechando el dominio de FidePaz.

7. Composición de la base de datos V1

✔ Verificado Conteo real de CREATE TABLE en mercagee_colonos.sql (55 tablas totales): 29 de WooCommerce (tienda en línea que este sitio no usa), 14 de plugins de terceros (LayerSlider, WP Google Maps, Action Scheduler, respaldos de File Manager) y 12 del núcleo de WordPress (usuarios, publicaciones, taxonomías, comentarios) — de estas últimas 12 se rescataron los datos reales de colonos, propiedades y pagos.

Veredicto de arquitectura

El sistema V1 operaba información financiera y de propiedad sobre una instalación de WordPress no estandarizada para ese propósito, con cuentas administrativas comprometidas y evidencia de inyección de spam SEO activa. La migración a V2.0 elimina por completo la dependencia de WordPress/WooCommerce, cierra los vectores de ataque conocidos (XML-RPC, wp-login.php, plugins de terceros) y reduce la base de datos a las tablas de negocio estrictamente necesarias.
